# Deploying Caravan Fresh to Render

This app is a Python/Flask web service with a SQLite database. It is **not** a
static site, so it needs a host that runs a persistent server process — Render
does exactly that, with a Netlify-style "connect your repo and it builds" flow.

---

## What's included for deployment

| File | Purpose |
|------|---------|
| `wsgi.py` | Production entrypoint. Creates the schema and seeds the database on first boot (idempotent). |
| `render.yaml` | Render Blueprint — provisions the web service, env vars and persistent disk automatically. |
| `Procfile` | Start command (also read by Railway / Heroku). |
| `runtime.txt` | Pins the Python version. |
| `requirements.txt` | Flask, Werkzeug, gunicorn. |
| `.env.example` | Template for local production-style runs. |

The production server is **gunicorn** with threaded workers, fronted by Render's
HTTPS proxy. Session cookies are automatically marked `Secure` + `HttpOnly`, and
`SECRET_KEY` is generated by Render.

---

## Option A — Deploy with the Blueprint (easiest)

1. Push this project to a GitHub/GitLab repo.
2. In Render: **New +  →  Blueprint**, and select your repo.
3. Render reads `render.yaml` and shows the service + disk it will create. Click
   **Apply**.
4. Wait for the build/deploy to finish, then open the generated
   `https://caravan-fresh.onrender.com` URL. Log in with
   `admin@caravanfresh.com` / `demo123`.

That's it — the database is created and seeded with the 70-store demo on first
boot.

## Option B — Deploy as a plain Web Service (no Blueprint)

1. In Render: **New +  →  Web Service**, connect the repo.
2. Settings:
   - **Build command:** `pip install -r requirements.txt`
   - **Start command:**
     `gunicorn --preload -w 2 -k gthread --threads 4 -b 0.0.0.0:$PORT --timeout 120 wsgi:app`
   - **Health check path:** `/healthz`
3. Add environment variables (Environment tab):
   - `ENV=production`
   - `SECRET_KEY=` → click **Generate**
   - `SEED_MODE=demo`
   - `DATA_DIR=/var/data`
   - `PYTHON_VERSION=3.12.6`
4. Add a **Disk**: mount path `/var/data`, size 1 GB (see the note below).
5. Create the service.

---

## ⚠️ Important: data persistence & the free tier

The SQLite file and uploaded evidence photos live in `DATA_DIR` (`/var/data`).

* **With a persistent disk (Starter plan or higher):** the mounted `/var/data`
  disk keeps your data across restarts and redeploys. This is what `render.yaml`
  configures and what you want for anything real.
* **On the Free plan (no persistent disk):** Render's filesystem is ephemeral and
  the service sleeps after ~15 min idle. On each cold start the database is empty,
  so the app **re-seeds the 70-store demo from scratch** — any data you entered is
  lost. That's fine for a demo/showcase, but not for real audit data.

To go live for real, use the Starter plan (keeps the disk) — or migrate to
PostgreSQL later (I can add that when you're ready).

## Controlling the initial data — `SEED_MODE`

Set the `SEED_MODE` env var to control what a fresh/empty database starts with:

| Value | Result |
|-------|--------|
| `demo` (default) | 70 stores, 5 officers, 70 owners, a month of activity, scores generated. |
| `minimal` | Config masters (checkpoints, KPIs, bands, weights) + one admin account. Clean for a real launch. |
| `none` | Tables only, no data. |

Changing `SEED_MODE` only affects an **empty** database; it never overwrites
existing data. To re-seed deliberately, clear the disk (or the DB file) and
redeploy.

## Other hosts

The same files work elsewhere with almost no change:

* **Railway / Heroku** — read the `Procfile` directly; add a volume mounted at
  `/var/data` and set the same env vars.
* **Fly.io / any Docker host** — run gunicorn with the Procfile command; mount a
  volume for `DATA_DIR`.
* **Any Linux VM** — `pip install -r requirements.txt` then run the gunicorn
  start command behind nginx.

## Local production-style run

```bash
cp .env.example .env          # edit SECRET_KEY
# load the env vars, then:
gunicorn --preload -w 2 -k gthread --threads 4 -b 0.0.0.0:8000 wsgi:app
```

(On Windows, gunicorn doesn't run — keep using `python run.py` for local dev, or
use `waitress-serve --listen=0.0.0.0:8000 wsgi:app` after `pip install waitress`.)
